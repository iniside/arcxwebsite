Troubleshooting¶

Symptom, cause and fix for what stops a document from showing or reacting. Quoted text is part of the log line (most lines start ArcRmlUI:); the log category is LogArcRmlUI, see Where to look.

No text is drawn¶

Cause: no loaded font matches the element's font-family, or none is set. The log has a warning that starts RmlUi: No font face defined.. It continues either Missing 'font-family' property, or with RmlUi's long message that says the specified font face has to be "successfully loaded" and names the family.

Fix: declare a font sheet and name its family in a style sheet (Project setup, Fonts). A font sheet that fails to load logs ArcRmlUI: font sheet '<path>' in the ArcRmlUI setting FontSheets does not exist (or is not a package path (package path), is unusable), and a face that fails logs failed to load font face.

The document does not open¶

  • OpenDocument returns false for an empty path, an unreadable head and while the world is cleaned up. Fix: pass the document's package path, check its <head>, and open it after the world is up (Documents).
  • A head error. The head is the part of the document between <head> and </head>. An unknown or repeated <meta>, or a value that is not allowed, is logged with the file and line as <file>(<line>): <meta name='input-mode'> needs 'game', 'menu' or 'all', got '<value>' (input mode). Fix: use a value from the head table of Documents; the validator reports the kind head.
  • The layer is wrong. Three cases:
  • <meta name='layer'> has unknown gameplay tag '<tag>': the tag does not exist.
  • layer '<tag>' is not in the ArcRmlUI settings LayerOrder: the tag exists but is not in Layer Order (Project setup, Layers).
  • ArcRmlUI: cannot open '<path>': the layer host has no layer '<layer>': the layer host has no widget layer for the tag.
  • ArcRmlUI: cannot open '<path>': a view of it already exists. The document has a view already; close it first.
  • ArcRmlUI: cannot open '<path>' without a local player world (a warning). The local player has no world at that moment, for example while a map is loading or the game is closing. Fix: open the document after the map has loaded.
  • ArcRml.Open: no local player in this world (a warning). The console command ran outside Play, where no player exists. Fix: run it during Play (Open the console).
  • ArcRmlUI: cannot open '<path>': pushing it onto layer '<layer>' failed. The layer's widget container did not add the document's widget.

Arrows or the pad do nothing¶

Check in this order:

  1. The document's input-mode is menu or all. A game document takes no keys (Documents).
  2. Something has focus. With focus nowhere the first arrow moves nothing, so give the entry element autofocus (Navigation).
  3. The target takes focus. A <button> does; a div or span needs tab-index: auto; nav: auto. Without nav an arrow does nothing and sends no navnotarget (Limits).
  4. In a project with menus, the input setup exists.

Back does nothing, or closes too much¶

  • Back does nothing, and the log has ArcRmlUI: '<path>': no keys are mapped to the CommonUI Enhanced Input back action. The project's input data has no key on its Back action. Complete the input setup; the validator reports it as input-mapping.
  • Back closes the document although a data-event-back handler ran. A call never stops the event. Add stopPropagation() to the handler, or leave it and let a child area's data-focus-parent take the Back. The order is in Navigation.

A field does not update¶

Cause: the document reads only Field Notify fields and redraws when the model broadcasts the change. A plain assignment in C++ is not seen, and neither is a Blueprint Set node that does not broadcast.

Fix: in C++ write the field with UE_MVVM_SET_PROPERTY_VALUE. In a Blueprint view model, set the Field Notify variable with its Set node, which the editor titles SET w/ Broadcast (Data binding, Blueprint view models). data-value cannot write a value back (Limits).

A call does nothing¶

Cause: call() runs nothing and logs a warning. The line about a 'vm:<path>' argument, the path of a view model (Events), is an error:

Log line Cause
'<Function>' is not a callable event function on '<Class>' The function does not exist, or is not a callable BlueprintCallable UFUNCTION that is non-const, not pure, not a network function and not a BlueprintNativeEvent or BlueprintImplementableEvent (Events).
'<Function>' received N arguments but takes M The argument count differs from the parameter count.
'<Function>' argument '<value>' does not convert to parameter '<name>' The value does not convert to the parameter's type.
'<Function>' object parameter '<name>' takes a 'vm:<path>' argument An object parameter needs 'vm:<path>'.
call('<path>', '<Function>') targets unknown view model The child path names no view model of the element's model.
call('<path>', '<Function>') on '<model>' has no live view model The model is not set yet.

The validator reports a missing function as unknown-function and a wrong count as call-arity (Validation). A click on a data-action other than close and open:<package path> under a <body> without data-model logs action '<action>' was clicked under a <body> or embedded document root that has no data-model; only close and open:<path> work without one.

Fix: make the name, the argument count and the argument values match the function in the view model class, and give the <body> a data-model.

A binding shows defaults¶

Cause: a view model that is not resolved still binds, from its class defaults, and its ArcResolved is false. This is the case before the first SetViewModel, the call that assigns a view model to a declaration, and for a preview model in a Shipping build or with ArcRml.PreviewHidden 1 (Editor preview).

Fix: for a manual model, call SetViewModel before you expect values; test ArcResolved in the document to show a fallback.

A hotkey does nothing¶

  • With the same data-hotkey on several elements, the click goes to the focused element or its nearest ancestor that has it; else to the first visible one in document order in the focused area, then in the document (an embedded tab's wrapper first). Another duplicate never fires, and there is no diagnostic. Fix: use each hotkey on one element (Navigation).
  • The log has ArcRmlUI: '<path>' input mapping '<mapping>' does not load as an Input Mapping Context (an error). The document opens, but its UI actions are unbound. Fix the path of the input-mapping meta.
  • A UI action that nothing handles logs UI action '<action>' has no handler, hotkey or cycle at the Log level. Fix: add a data-hotkey or a handler for it.
  • A data-event-uiaction handler consumes the action only if it also calls stopPropagation(); otherwise the hotkey runs as well.
  • The action must be in the document's input-mapping context, and the document needs an input-mode other than game (Input and gamepad).

A document is missing in a packaged build¶

Cause: with Package Everything on, every document of every content root ships. With it off, a document that is neither in Paths to Package nor reached from a shipped document by a frame, a literal open: target or a reference of a Blueprint or data asset is not packaged (Project setup, Packaging). A data-action built from data (data-attr-data-action, data-attrif-data-action or {{ }}) is not followed; the cook logs '<document>' builds a data-action from data as a warning.

Fix: add the target to Paths to Package. For a document inside a Game Feature plugin, add the Package RML Documents action to its GameFeatureData instead (Project setup, Packaging).

Where to look¶

  • The log category LogArcRmlUI; a diagnostic line is <file>(<line>): <message>. Warnings and errors outside Shipping also show in a bar over the viewport.
  • The editor's Message Log, the ArcRmlUI log pages, and the preview's Diagnostics panel (Working with documents).
  • The validator: it finds most of the above before the document opens.
  • The inspector: for an element with the wrong size or a style that does not apply, it shows the box model and the rules that reach the element, with their file and line.
