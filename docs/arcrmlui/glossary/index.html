Glossary¶

The terms this guide uses, each with the page that explains it. Concepts introduces them in order.

Component¶

An .rml file whose root is <component>, with declared props and slots. A document imports it with <dc-import>, and its markup is expanded into the document when the document is compiled. See Components.

Content rect¶

The part of the screen a document is laid out in. It is the screen without the edges a TV may cut off, no wider than the widest shape the UI may take, and centred; the document's background still fills the whole screen. See Screen size.

Content root¶

The Content folder of the project (/Game) or of a plugin in the project that can contain content (/MyPlugin). Documents and style sheets live in a content root. See Concepts.

CSS px and dp¶

A px in an .rcss file is multiplied by the UE DPI scale (the dp ratio) before layout, so it is one screen pixel only at scale 1.0; dp is multiplied the same way. See Screen size.

Document¶

An .rml file with a <head> and a <body>, styled by .rcss sheets and named by package path, such as /Game/UI/Rml/Menu.rml. It opens per local player. See Documents.

Field Notify¶

Unreal's field notification: a view model property or function marked to broadcast its changes. A document reads only Field Notify fields, and updates when the model broadcasts a change. See Data binding.

Focus area¶

An element with data-focus-area="<name>": an arrow inside it moves only to targets in the same area until focus is told to leave. See Navigation.

Frame¶

A document that shows other documents, its tabs, one at a time in its arc-embed element. It decides the layer and the input mode of its tabs. See Frames and tabs.

Input mode¶

<meta name="input-mode">: game (default) leaves keys and mouse to the game, menu gives them to the document, all gives them to both. See Concepts.

Keep-alive and park¶

A document with <meta name="keep-alive" content="true"> is parked when it closes instead of destroyed: it draws nothing and takes no input, and the next open brings it back as it was left. See Keep-alive and preload.

Layer¶

The UI.Layer.* gameplay tag a document opens on, from <meta name="layer"> (default UI.Layer.Game). Layers stack in the order of the Layer Order setting. See Documents.

Local player¶

One player of the game on this machine; a split-screen game has more than one. A document opens per local player. See Screen size, cursor and local players.

Package path¶

The name of a document or file by its content root and folder, such as /Game/UI/Rml/Menu.rml. See Concepts.

Preload¶

PreloadDocument loads a document, lays it out and parks it before its first open, so that open is fast. See Keep-alive and preload.

RCSS¶

The style sheet language of the plugin, CSS-like, in .rcss files. See CSS support.

Resolver¶

A C++ class derived from UMVVMViewModelContextResolver that creates a view model instance for the resolver source. See Source: resolver.

RML¶

The markup language of documents, HTML-like, in .rml files. See Documents.

Shipping build¶

A packaged build made with Unreal's Shipping configuration. ArcRml.Inspect, the in-game error bar and the sample commands are not in it.

Source¶

Where a view model instance comes from, named by its <viewmodel> declaration: create, context, resolver, manual or path. See Concepts.

Tab¶

A document whose <meta name="frame"> names a frame document; it is shown inside that frame. Opening a tab opens its frame. See Frames and tabs.

UI action¶

An action of the document's Input Mapping Context that fires; the document receives it as a uiaction event with the action's name in ev.action. See UI actions.

UI update¶

One pass of the plugin's UI thread: messages from the game thread, input, bindings, styles, layout and drawing. See The update cycle.

View¶

The loaded instance of a document for one local player: what opens, parks and is discarded. See Keep-alive and preload.

View model¶

An Unreal MVVM view model (UMVVMViewModelBase) a document reads Field Notify fields from and calls functions of. See View models.
