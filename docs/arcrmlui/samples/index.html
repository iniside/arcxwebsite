Samples¶

The companion plugin ArcRmlUISamples holds small samples, one feature each, every one in its own folder: the document, its style sheet, a README.md and, under Source/ArcRmlUISamples/<Sample>/, its C++ (BlueprintViewModel, Converter and EditorPreview have none). Run one to see a feature working, or copy its files into your project as a starting point. The guide's code blocks are copied from these files.

Install¶

The samples are in the Arc Lunzo Samples repository on GitHub. To run them without a project of your own, open its ArcRmlUIHost.uproject, which has them set up. To add them to your project:

  1. Copy the ArcRmlUISamples plugin folder (Plugins/ArcRmlUISamples of the repository) into your project's Plugins folder; put it nowhere else, or its content is not found. The plugin has a C++ module (Win64), so the project must build C++.
  2. Add the samples' font sheet to the font settings, in Config/DefaultGame.ini: +FontSheets=/ArcRmlUISamples/UI/Rml/Fonts/Fonts.rcss in [/Script/ArcRmlUI.ArcRmlUISettings].
  3. For the samples list and the samples that take keys and the gamepad, the project needs the input setup; the plugin's /ArcRmlUISamples/Input/ assets provide one.
  4. Restart the editor.

Run a sample¶

Play in the map L_ArcRmlSamples (/ArcRmlUISamples/Maps/). A list of the samples shows in a column at the right edge, followed by a Blueprint group. Click a sample to open it. A sample on the menu layer hides the list until it closes; Back (Esc or gamepad B), the sample's own close, or the "Back to samples" button in the top-left corner closes it and the list shows again (Events needs a second Back; BackAndParent does when focus is in its detail area). FirstScreen opens beside the list. Choosing another sample closes the one opened last.

The console is the second way, and the one to script:

ArcRmlSamples.Open FirstScreen
  • ArcRmlSamples.Open <Sample> runs the sample's C++ open function, the code its page quotes; the list does the same.
  • ArcRmlSamples.OpenBP <Sample> runs the Open function of the sample's Blueprint Function Library BP_<Sample>_Open, for the samples that have one; the list's Blueprint group does the same.
  • ArcRmlSamples.Close closes the document the last open returned.
  • Converter has no open function: in the game ArcRml.Open /ArcRmlUISamples/UI/Rml/Converter/Page.rml.
  • EditorPreview has no open function: double-click EditorPreview.rml in the Content Browser, or in the game ArcRml.Preview /ArcRmlUISamples/UI/Rml/EditorPreview/EditorPreview.rml.

The list and these commands exist outside Shipping builds.

In the table below, the last column names the console command; "Open" is ArcRmlSamples.Open and "OpenBP" is ArcRmlSamples.OpenBP.

Packaging the samples¶

With Package Everything on (the default) a packaged build ships the samples' documents. With it off, add their folder to Paths to Package: +PathsToPackage=/ArcRmlUISamples/UI/Rml in [/Script/ArcRmlUI.ArcRmlUISettings] of Config/DefaultGame.ini. Most samples open their documents from C++ by a path string, which the cook does not see.

The samples' Blueprints (the BP_*_Open classes) and Widget Blueprints (WBP_Sample_*) are also loaded from C++ by a path string, so the cook does not see them either. Add the folder to Additional Asset Directories to Cook in Project Settings > Packaging (+DirectoriesToAlwaysCook=(Path="/ArcRmlUISamples") in [/Script/UnrealEd.ProjectPackagingSettings] of Config/DefaultGame.ini). The host project has both lines.
