ArcRmlUI¶

ArcRmlUI lets you build game UI as documents written in HTML-like markup (RML) with real CSS-like styling (RCSS). A document reads its data from Unreal MVVM view models and calls their functions, and it takes mouse, keyboard and gamepad input through CommonUI and Enhanced Input.

What you can build¶

  • Documents and layers: screens that open and close on CommonUI layers.
  • Data binding and lists: fields, conditions and repeated rows from a view model.
  • Events: buttons and keys that call view model functions.
  • Components: reusable pieces of a document.
  • Focus areas and gamepad navigation, with input and gamepad setup.
  • Text fields and drag and drop.
  • Frames and tabs.
  • Themes and animations.
  • Localization.
  • World markers: UI that follows a point in the world.
  • Editor preview: see a document in the editor with sample data.
  • Validation: check documents and their bindings before you run the game.

Is it for you¶

  • Unreal Engine 5.8, Win64.
  • Opening a document and writing a view model work from Blueprint. Struct lists (FArcRmlStructList) and view model resolvers are C++ (Struct lists, Source: resolver).
  • You write the documents and style sheets in HTML and CSS syntax; the guide does not teach either. For what differs from a web page see Coming from HTML and CSS.
  • A document opens on a CommonUI layer of the local player's viewport. Documents open only through OpenDocument, not inside a Widget Blueprint: no UMG widget hosts a document. To show one, open it from C++ or Blueprint, or with ArcRml.Open (Quick start).

What you get¶

The ArcRmlUI plugin. The samples plugin and the demo plugin are available separately on GitHub.

Where to start¶

  1. Quick start: open and close a first document from C++ or Blueprint.
  2. Project setup: enable the plugin and add the settings a project needs.
  3. Working with documents: edit, save and see the change.
  4. Concepts: the terms the rest of the guide uses.
  5. Samples: the companion samples plugin, one small sample per feature, and how to run each one.
  6. Walkthrough: one screen of the demo game UI, read part by part.
