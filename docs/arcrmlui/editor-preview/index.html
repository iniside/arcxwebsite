Editor preview¶

A document can declare a view model whose data is a JSON file. The data stands in for the real view model, so a designer sees real-looking values without code, in the editor and in a game.

The declaration and the JSON¶

EditorPreview.rml
<viewmodel name="player" preview="Preview/EditorPreview.json"/>

The path is relative to the document. A preview declaration takes no class, no source attribute (create, context, resolver, manual or path), no settable and no on-close.

Preview/EditorPreview.json
{
    "Name": "Aldric",
    "Level": 7,
    "Health": 0.8,
    "Accent": { "$colour": "#3399ffff" },
    "bLowHealth": false,
    "Items": ["Stone axe", "Oak staff", "Iron shield"],
    "$variants": {
        "LowHealth": {
            "Health": 0.15,
            "Accent": { "$colour": "#e04040ff" },
            "bLowHealth": true,
            "Items": ["Stone axe"]
        }
    }
}
  • The root is an object; each top-level key is a field of the model. Values are booleans, integers, numbers, strings, arrays and objects. null is an error.
  • A colour is { "$colour": "#rrggbbaa" }, and $colour is the object's only member.
  • $variants is an object of named variants. A variant lists the fields it overrides; every other field keeps its base value. An overridden field is replaced as a whole, so Items in LowHealth is the complete list. A variant can name only fields the base data has, else the file does not load and an error is logged.

The document reads these fields like any other model's: {{ Name }}, data-if="bLowHealth", data-for="item : Items".

When the data shows¶

The data shows in the editor preview and in a game with a local player, when all of these hold:

  • The build is not a Shipping build.
  • The console variable ArcRml.PreviewHidden is 0. It applies to documents opened afterwards and does not exist in Shipping.
  • The JSON file exists.

Otherwise the model binds default values and its field ArcResolved is false. The sample shows a fallback line with it:

EditorPreview.rml
<p data-if="!ArcResolved">No preview data is shown.</p>

Never make live behaviour depend on preview data. A function called on a preview model only logs, so a button that calls one does nothing except log.

Open the preview tab¶

In the Content Browser, double-click EditorPreview.rml: the preview tab opens and shows the sample with the base data, "Aldric, level 7", a health bar and three items. Its toolbar has Resolution, Variant (Base and the variants of the document's preview files), Theme, Background, Inspect, Open in text editor and Reload. Beside the view, the panels are Bindings, Diagnostics, Inspector and Input:

  • Bindings lists the document's view models; for a preview model it edits the JSON data: add keys, rename or remove them, and override a value in the selected variant.
  • Diagnostics lists the errors and warnings of the open document.
  • Inspector shows the elements you pick with Inspect: tree, box model and rules by selector (Debugging layout).
  • Input lists the actions of the document's input mapping context for keyboard or gamepad. After you choose gamepad, click the preview view once with the mouse before you use a pad: the view gets pad input only while it has focus.

The Variant menu ends with Add variant..., which asks for a name and adds an empty variant to every JSON preview file of the document that lacks it. It is disabled when the document has no JSON preview file that loaded.

In a game¶

In a running game, open the console and type:

ArcRml.Preview /ArcRmlUISamples/UI/Rml/EditorPreview/EditorPreview.rml LowHealth

ArcRml.Preview <Path> [Variant] opens the document with a variant and reopens it when it is open. <Path> is the document's package path. Leave out the variant for the base data.

You should see the sample panel in the game with "Aldric, level 7", the line "Health is low." and the one item "Stone axe". ArcRml.Close /ArcRmlUISamples/UI/Rml/EditorPreview/EditorPreview.rml or the sample's Close button closes it.
